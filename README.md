# Valheim Resource Manager

Локальная панель учёта ресурсов Valheim с русским интерфейсом: C#-плагин BepInEx → HTTP API → SQLite → WebSocket → React. Данные мира читаются; метки сундуков, зоны и минимальные запасы сохраняются отдельно от игры.

**Статус: рабочий MVP 0.1.0.** Backend, интерфейс, парсер настоящего сохранения и автоматические проверки работают. Запуск C#-плагина внутри игры и сценарий «положил 40 дерева → увидел +40 в панели» пока **UNVERIFIED**. Целевые 1–2 секунды в игре не измерены. Демо проверяет программную цепочку на синтетических данных.

## Возможности

- Каталог ресурсов: поиск, категории, сортировка, карточки и таблица.
- Карточка ресурса с количеством в каждом известном сундуке, координатами XYZ и временем наблюдения.
- Локальные названия сундуков, круговые складские зоны X/Z, минимальные запасы и дефициты.
- Сохранение последних остатков при отключении источника или выгрузке сундука.
- Раздельные статусы `LIVE`, `STALE`, `OFFLINE`, `SNAPSHOT` и явное обозначение частичного охвата.
- Изолированное демо: добавление 40 дерева, перенос, отключение и восстановление.
- Дополнительное чтение завершённых сохранений поддерживаемого формата без записи в игровые файлы.

Движущиеся контейнеры, транспорт, надгробия и инвентарь игрока исключены из live-сборщика. Полный охват мира не обещается. Движка рецептов и планирования крафта пока нет.

## Требования

Для панели:

- Windows и PowerShell 5.1 для `.cmd`/`.ps1` помощников.
- Node.js **24 или новее** с npm: backend использует встроенный `node:sqlite`.
- Современный браузер. При первой установке зависимостей нужен интернет.

Для подключения игры:

- Собственная установленная Valheim. Исследованная версия — **1.0.20**; плагин отклоняет другие версии.
- Уже установленный BepInEx. Проверенная локальная сборка использовала **5.4.23.5** и Harmony из этой установки.
- .NET SDK для сборки C#; проверена сборка SDK **9.0.200**, target `netstandard2.1`, ссылки берутся из локальной игры и BepInEx.
- Установщик дополнительно проверяет точный SHA256 исследованной `assembly_valheim.dll`. Совпадения номера версии недостаточно: неподтверждённая DLL будет отклонена.

Python **3.11+** нужен только для snapshot-парсера и его тестов. Репозиторий не содержит Valheim/Unity/BepInEx/Harmony DLL, игровых ассетов, сохранений, рабочих баз и токенов. Библиотеки для сборки нужно получить в своей установленной игре; проект не скачивает и не переустанавливает их.

## Установка и запуск панели

```powershell
git clone https://github.com/HarryCane1995/valheim-resource-manager.git
cd valheim-resource-manager
npm.cmd ci
npm.cmd run build
npm.cmd start
```

Откройте [http://127.0.0.1:37841](http://127.0.0.1:37841). Backend создаст `data/live.sqlite`, отдельную `data/demo.sqlite` и приватный `data/ingest-token.txt`. В свежем клоне реальная база пуста. Демо включается явной кнопкой в интерфейсе и не записывает данные в реальную базу.

В Windows также можно запустить **START-RESOURCE-MANAGER.cmd**: помощник установит зависимости при отсутствии `node_modules`, соберёт интерфейс, запустит backend в фоне и откроет браузер. **STOP-RESOURCE-MANAGER.cmd** останавливает только собственные процессы backend/watcher с проверкой командной строки. Игру помощники не закрывают.

При запуске через `npm.cmd start` остановка — `Ctrl+C` в том же терминале. Порт `37841` должен быть свободен. Обычный запуск обслуживает production build из `dist/`.

Для разработки оставьте backend работающим и выполните `npm.cmd run dev`; откройте Vite-панель на `http://127.0.0.1:5173`. Proxy поддерживает HTTP и WebSocket: он заменяет Origin на адрес backend только при точном совпадении входного Origin с loopback Host (`127.0.0.1` или `localhost`) с допустимым портом. Посторонний Origin сохраняется и отклоняется backend с `403`. Строгая политика доступа backend не ослаблена; этот путь проверен отдельным изолированным интеграционным тестом.

## Подключение к Valheim

1. Запустите панель, чтобы backend создал локальный токен.
2. Соберите **собственный** плагин по своей установке:

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File .\plugin\build.ps1 -GameDirectory "C:\Program Files (x86)\Steam\steamapps\common\Valheim"
   ```

   При другом расположении замените значение `-GameDirectory`. Результат: `plugin/bin/Release/netstandard2.1/ValheimResourceManager.dll`. Сборка сама не изменяет игру. Два известных предупреждения MSB3277 о Unity facade описаны в [TEST_REPORT.md](TEST_REPORT.md).

3. Установите плагин и его собственную конфигурацию:

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install-plugin.ps1 -GameDirectory "C:\Program Files (x86)\Steam\steamapps\common\Valheim"
   ```

   **INSTALL-GAME-PLUGIN.cmd** вызывает тот же установщик для стандартного пути Steam. Установщик проверяет игровую DLL, наличие BepInEx и отсутствие чужих файлов по целевым путям. Он добавляет только собственную DLL и `BepInEx/config/local.valheimresourcemanager.cfg`, переносит токен локально без его вывода и сохраняет квитанцию в `data/`. При несовпадении сборки или уже существующем чужом файле установка останавливается.

4. При следующем обычном запуске Valheim BepInEx загрузит плагин. Копирование DLL не загружает её в уже работающую игру. Оставьте backend работающим, загрузите мир и подойдите к базе. В локальном BepInEx-журнале ожидаются `Read-only integration ready` и `Observing world`.
5. Проверьте игровой источник и статусы в панели. В разделе складских зон задайте реальный центр X/Z и радиус базы: первоначальная зона радиусом 100 м — только редактируемое предложение вокруг первого наблюдения.
6. Выполните ручную проверку: положите ровно 40 дерева в поддерживаемый сундук, проверьте +40 и правильное место хранения, затем изъятие/перенос и уход с базы. До выполнения этого сценария live-критерий остаётся неподтверждённым.

Плагин отправляет данные только на loopback HTTP и требует локальный `X-VRM-Token`. Пример структуры конфигурации: [plugin/local.valheimresourcemanager.cfg.example](plugin/local.valheimresourcemanager.cfg.example). Не публикуйте заполненный CFG, токен, журналы игры и `data/`.

### Удаление и обновление плагина

**UNINSTALL-GAME-PLUGIN.cmd** использует локальный manifest и независимую квитанцию. Он удаляет только добавленные этим установщиком DLL/CFG с совпадающими хешами. Изменённые и чужие файлы сохраняются. Уже загруженный плагин останется в памяти до обычного закрытия игры.

Автоматической перезаписи другой сборки нет. Для обновления сначала нужен проверенный откат записанной установки, затем сборка и повторная установка. После обновления Valheim требуется новый аудит API/формата: не обходите проверку версии или SHA256 ради установки.

## Резервное чтение сохранений

Snapshot — отдельный источник; он отражает **сохранение мира**, а не мгновенное перекладывание предметов. Поддерживаются только исследованные chunk-форматы 40–42, inventory 108–110 и согласованное завершённое поколение `_main.N.ok` с mapping/metadata/chunk файлами. Старые монолитные `.db` и произвольные будущие форматы не поддерживаются.

Однократное чтение и импорт, с подстановкой своего каталога завершённого сохранения:

```powershell
python .\scripts\read_snapshot.py --world-folder "C:\path\to\completed-world-folder" --output ".\output\private-snapshot-check" --import-url "http://127.0.0.1:37841/api/snapshot" --token-file ".\data\ingest-token.txt"
```

Каталог `--output` должен быть новым. CLI сохраняет там manifest, payload **и копии входных файлов** для проверки; это приватные данные, исключённые из Git. Входные игровые файлы открываются только для чтения, хешируются и повторно проверяются перед импортом. Поля истории игроков отбрасываются парсером, но исходные файлы всё равно являются приватными.

Для watcher вручную создайте приватный `data/snapshot-source.json`:

```json
{
  "worldFolder": "C:\\path\\to\\completed-world-folder",
  "worldId": "YOUR_WORLD_UID_AS_STRING"
}
```

Укажите настоящий UID из локального snapshot manifest строкой. После этого запустите `python .\scripts\watch_snapshot.py` либо заново запустите Windows-помощник панели. Watcher проверяет новые завершённые поколения каждые 5 секунд, пропускает тяжёлое чтение при активном live-источнике и сохраняет payload/manifest без копирования всех чанков. Сейчас он рассчитан на один настроенный каталог/мир; автоматического выбора мира и мастера настройки нет. Переход watcher на следующее **реальное** поколение ещё не подтверждён игровым тестом.

## Актуальность и ограничения

| Статус | Значение |
|---|---|
| `LIVE` | Активный источник подтвердил этот контейнер в текущем сеансе не более 15 секунд назад |
| `STALE` | Источник активен, но наблюдение контейнера старше или относится к предыдущему сеансу |
| `OFFLINE` | Контакт с источником отсутствует более 12 секунд; последние остатки сохранены |
| `SNAPSHOT` | Данные получены из завершённого сохранения; runtime ZDOID не подтверждён |

Heartbeat сам по себе не обновляет время содержимого выгруженного сундука. Отсутствие сундука в пакете не означает уничтожение: остатки исключаются только при явном подтверждении уничтожения. Охват штатных сборщиков остаётся `partial`, включая host/server.

В исследованном сохранении runtime ZDOID пересоздаётся при загрузке. Для неподвижных сундуков используется локальный ключ из UID мира, prefab hash и точных float32-битов XYZ; настоящий runtime ZDOID хранится отдельно строкой. Перемещение сундука меняет этот ключ, а совпадающие prefab и точные координаты создают конфликт. Неизвестные prefab-хеши сохраняются без догадок о названии.

В приватной локальной проверке parser → SQLite → UI прочитаны 151 распознанный сундук и 21 233 единицы. Это частичный snapshot, а не независимая проверка сундуков внутри игры. Исходный мир, координаты, его идентификаторы и скриншоты с реальными данными не поставляются. Подробности и оставшиеся проверки — в [TEST_REPORT.md](TEST_REPORT.md), устройство системы — в [ARCHITECTURE.md](ARCHITECTURE.md).

```powershell
npm.cmd ci
npm.cmd run build
npm.cmd test
python -m unittest discover -s scripts -p "test_snapshot.py" -v
```

Изолированные проверки установщика требуют предварительно собранную собственную DLL и локальную исследованную игровую DLL, которая только читается и копируется во временный mock-каталог:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\test_install.ps1 -AuditedAssemblyPath "C:\Program Files (x86)\Steam\steamapps\common\Valheim\valheim_Data\Managed\assembly_valheim.dll"
```

Перед отправкой изменений в GitHub добавьте только предназначенные для публикации файлы в Git index и выполните проверку именно публикуемого содержимого:

```powershell
python .\scripts\audit_publication.py
```

Backend слушает только `127.0.0.1:37841`, проверяет Host/Origin, не открывает CORS посторонним сайтам и ограничивает JSON-пакет 3 МиБ. Это локальная утилита без учётных записей и TLS: доступ процессов того же компьютера к данным не изолирован. Не публикуйте backend в интернет через туннель или reverse proxy без отдельной модели безопасности.
