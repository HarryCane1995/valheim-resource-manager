# Первый тест на компьютере другого игрока

Комплект: portable-панель 0.3.0 и собственный плагин Valheim Resource Manager 0.2.0. Для Windows x64, Valheim **1.0.20** и уже установленного BepInEx. Проверенная локальная версия BepInEx — **5.4.23.5**; другие версии отдельно не проверялись. Node.js, Python и .NET SDK игроку не нужны.

## Подключение

1. Распакуйте весь ZIP в отдельную доступную для записи папку. Запускайте EXE из распакованной папки.
2. Закройте Valheim обычным способом.
3. Запустите `ValheimResourceManager.exe`. Приложение создаст собственные `data` и `localdata`; оставьте его открытым.
4. Из комплекта скопируйте папку `BepInEx/plugins/ValheimResourceManager` в существующую папку `Valheim/BepInEx/plugins/`. В ней должна оказаться собственная DLL по пути `Valheim/BepInEx/plugins/ValheimResourceManager/ValheimResourceManager.dll`.
5. Скопируйте `local.valheimresourcemanager.cfg.example` в `Valheim/BepInEx/config/`, назвав файл точно `local.valheimresourcemanager.cfg` (без `.example` и `.txt`). Если наш плагин или его CFG уже установлены, сначала сохраните их отдельные копии; не заменяйте чужие моды и настройки.
6. В папке EXE откройте `data/ingest-token.txt` обычным Блокнотом. Скопируйте значение в строку `Token =` нового CFG вместо `REPLACE_WITH_LOCAL_BACKEND_TOKEN`. Оставьте `Endpoint = http://127.0.0.1:37841/api/ingest` и пустой `SourceId =`. Сохраните файл. У каждого компьютера свой токен; его не нужно присылать другим участникам.
7. Запустите Valheim, загрузите нужный мир или подключитесь к серверу. Подойдите к базе и откройте тестовый сундук. В приложении оставьте режим «Авто: активный мир» и дождитесь подключения источника.

BepInEx загрузит DLL при обычном запуске игры. Папки `data`/`localdata` со старого компьютера для этого теста не переносятся. Уже установленные моды на сундуки остаются на месте.

## Что проверить

1. Игра запускается с прежними модами; панель показывает правильный мир и подключённый источник.
2. В карточке выбранного ресурса находится именно нужный сундук. Запишите исходное количество дерева в нём.
3. Положите ровно **40 дерева**. Проверьте **+40** в том же сундуке и измерьте время обновления.
4. Заберите те же 40. Проверьте возврат исходного количества.
5. Перезапустите только панель. Проверьте восстановление связи и сохранность последних остатков.
6. Проверьте F11 и закрытие карточек щелчком снаружи.

Достаточно сообщить версию игры/BepInEx, названия модов на сундуки, результат +40/−40 и примерную задержку. Если нужна диагностика журнала, сначала удалите токены, личные пути, имена/UID мира и другие приватные данные.

## Границы этого теста

- У каждого игрока собственная локальная база; наблюдения разных компьютеров автоматически не объединяются. Метки, минимальные запасы и назначения категорий также локальные. Новый мир начинает с общего минимума 0 до его отдельной настройки.
- На клиенте чужого сервера видны доступные ему загруженные сундуки. Полный охват чужого мира не подтверждается. Привязка области 500 м к кровати хоста автоматически получается только у хоста; на удалённом клиенте эта привязка пока недоступна.
- Сборщик читает стандартные `Container/Inventory`. Совместимость с конкретным набором модов и работа на втором компьютере требуют этого игрового теста. Текущие сборки EXE и DLL не подписаны сертификатом издателя.
- «Выбрать сохранение» — отдельный резервный режим SNAPSHOT для поддерживаемых локальных сохранений. Для первого live-теста выбирать чужое сохранение не требуется.

## Что входит в ZIP

Только EXE, наша DLL, пример CFG с пустым индивидуальным SourceId и заглушкой токена, эта инструкция и SHA256SUMS.txt. Игровых библиотек, BepInEx/Harmony, игровых картинок, сохранений, рабочих SQLite, журналов и заполненных конфигов нет.
