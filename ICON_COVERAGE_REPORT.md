# Покрытие настоящими пиктограммами — PASS 2

Проверка от 17 октября 2026 года выполнена на локально установленной **Valheim 1.0.20**. Изображения получены из настоящих игровых Sprite, без генерации и без массового скачивания wiki. Файлы PNG остаются на компьютере владельца игры и исключены из публичного Git-репозитория.

Числа 994, 1075 и 969 измеряют разные вещи: предметы с основной картинкой, ссылки на варианты и уникальные байтовые файлы. Несколько предметов или вариантов могут законно использовать один и тот же Sprite. Исходные идентичности предметов при этом не объединяются.

Для найденных Sprite экспорт дал **1075 из 1075** результатов. Для всех 1519 зарегистрированных определений наличие основной пиктограммы составляет **994/1519 ≈65,44%**. Оставшиеся 525 определений включают внутренние ItemDrop атак NPC и другие служебные записи; картинка для них не выдумывается. Отдельно все **271 предмет** проверенного реального снимка базы имеют локальную основную пиктограмму. Этот результат относится к наблюдавшемуся инвентарю, не ко всем возможным предметам модов или будущих обновлений.

Три ссылки из исходного ObjectDB не разрешены в определения и остаются вне этих 1519 записей. Наличие иконок у этих трёх записей **не подтверждено**. Покрытие всего сериализованного ObjectDB — **1519/1522 =99,80%**, runtime-проверки текущего игрового реестра пока нет.

## Источник и техника извлечения

Проверенный источник — установленные игровые assets и AssetBundles. [ValheimIconExporter](tools/ValheimIconExporter/export_items.py) читает `ObjectDB.m_items`, `ItemDrop.m_itemData.m_shared.m_icons` и точные Sprite-ссылки. UnityPy восстанавливает текстуру/атлас и область Sprite; экспортёр возвращает исходный прозрачный холст с учётом `m_Rect` и `textureRectOffset`, сохраняет RGBA PNG без замены композиции или увеличения изображения. Исходные игровые assets не изменяются.

Связь с предметом основана на точном prefab ID и исходной Sprite-ссылке. Каждый вариант сохраняет свой индекс в `metadata.iconVariants`. Для основного изображения используется полученный из игры `iconKey`; в интерфейсе он превращается в `/api/icons/<sha256>.png`. Ключ — SHA-256 точных PNG-байтов. Размер отображения 20–24 px в компактной таблице не меняет исходные локальные PNG.

Код также содержит [runtime-экспортёр](plugin/RegistryExporter.cs), который работает в главном потоке Unity и читает `SharedData.m_icons`. Он использует UV и геометрию Sprite, собственный временный `RenderTexture`, `ReadPixels`, затем PNG. Такой путь рассчитан на Texture2D, недоступные для прямого CPU-чтения. Состояние `RenderTexture.active` восстанавливается, временные объекты уничтожаются, исходные текстуры не записываются. Ограничения и тесты приведены в [runtime-инструкции](tools/registry-runtime/README.md).

Новый runtime-путь собран и проверяется отдельно алгоритмическими тестами; фактическое выполнение GPU-экспорта в текущей игровой сессии **не подтверждено**. Игровой процесс ради проверки не прерывался. Числа в таблице выше получены именно успешным офлайн-извлечением установленных assets.

## Локальное воспроизведение

Запуск и зависимости приведены в [ITEM_REGISTRY.md](ITEM_REGISTRY.md). Экспортёр создаёт:

- `localdata/icons/<sha256>.png` — защищённые игровые картинки, локально.
- `localdata/registry/items.json` — связь prefab, вариантов и ключей картинок.
- `localdata/registry/extraction-report.json` — счётчики и подробности пропусков.

Backend обслуживает PNG только из каталога `localdata/icons/` по ключам из 64 строчных hex-символов. Загрузка через API требует локальный токен, `Content-Type:image/png`, размер до 512 КиБ, корректную сигнатуру, допустимые размеры и совпадение SHA-256. Каталог или произвольный файловый путь нельзя выдать за изображение. Запросы с постороннего Origin и Host отклоняются. Изображения из других источников автоматически не подмешиваются.

Если картинка отсутствует или не загрузилась, предмет сохраняет своё имя, ID, количество и диагностику. Интерфейс показывает нейтральное сокращение названия. Такая заглушка не считается настоящей иконкой и не включается в число найденных изображений.

## Права и границы публикации

Источник A — локальная копия установленной игры. Право владеть и запускать игру само по себе не устанавливает право распространять её изображения. Подтверждённого разрешения на публикацию игровых PNG вместе с проектом нет; они **не публикуются**. Экспортёр не выдаёт пользователю каких-либо дополнительных прав на графику Iron Gate/Coffee Stain. Условия использования своей копии игры и дальнейшей передачи изображений владелец проверяет отдельно.

Источник B — Valheim Wiki — в этом проходе не понадобился. Изображения с wiki не скачивались, лицензия на распространение конкретных wiki-файлов для этого проекта не подтверждалась. Общая лицензия текста wiki не используется как разрешение копировать игровые изображения.

В публичном репозитории находятся исходники обоих экспортёров, формат манифеста, проверки и эти инструкции. В нём отсутствуют настоящие игровые PNG, DLL Valheim, сохранения, реальные SQLite, приватные отчёты и личные пути. Папка `localdata/` целиком исключена из Git.

## Что проверено и что остаётся

Подтверждены реальные источник и количество экспортированных Sprite, наличие всех 969 файлов, их SHA-256, PNG-заголовки и размеры. Проверена связь всех 271 предмета реального сохранённого инвентаря с доступными локальными пиктограммами. Проверка байтового API отдельными синтетическими PNG не подменяет эти реальные результаты.

Не подтверждены иконки трёх неразрешённых ссылок ObjectDB, определения и изображения runtime-модов, работа нового GPU-пути внутри живого Unity и поведение после будущих обновлений игры. Семантическое визуальное сопоставление каждого из 1075 вариантов вручную не проводилось; связь получена из исходных игровых указателей. Прочие ограничения и результаты сборки перечислены в [TEST_REPORT.md](TEST_REPORT.md).
