# Экспорт реестра и настоящих пиктограмм из работающего Valheim

Экспортёр встроен в C#-плагин `plugin/RegistryExporter.cs` версии 0.2.0. Он работает в Unity после обычной загрузки плагина BepInEx и входа в мир. Подключение DLL к уже работающему процессу не производится. Не перезапускайте игровую сессию ради экспорта: обновлённый плагин сможет загрузиться при следующем обычном запуске игры.

## Реальный источник

Каждый проход читает текущий `ObjectDB.instance.m_items`, затем `ItemDrop.m_itemData.m_shared` каждого определения. Экземпляры игровых объектов не создаются; `ItemDrop.Awake`, изменение реестра, прав владения, прогрессии и сохранений не вызываются. Каталог содержит точное имя prefab, `prefab:<имя>` в качестве основного ID, числовой stable hash, RU/EN, тип, максимальную стопку, качество, варианты и другие доступные свойства. Подкатегория соответствует исходному `ItemType`; категорию рассчитывает backend, сохраняя локальные переопределения.

Русские и английские строки читаются из CSV, перечисленных настоящим `LocalizationSettings`. Приватный CSV-парсер поддерживает кавычки, запятые и переносы внутри полей. Словарь активного языка читается для дополнений модов. Экспортёр не создаёт собственный `Localization`, не переключает язык игры и не записывает настройки. Для мода, который зарегистрировал только активный язык, перевод другого языка остаётся отсутствующим с диагностикой. Владение prefab конкретным модом без точного источника отмечается `UNKNOWN`.

Каждые 30 секунд сравниваются текущий ObjectDB, ссылки/имена prefab, основные свойства и ссылки пиктограмм. Изменения запускают новый проход; неизвестное имя предмета из реального контейнера также запрашивает безопасную переиндексацию. Один и тот же неразрешённый ID не вызывает бесконечные повторные сканирования. Записи инвентаря отдельно сохраняют `quality` и `variant`; отображаемое название не используется как ключ.

## Пиктограммы

Источником служит `SharedData.m_icons`. Используются настоящие вершины, треугольники, UV, pivot и pixelsPerUnit каждого Sprite. Из текстуры или атласа читается только необходимая область через собственный временный `RenderTexture` и `ReadPixels`. Поэтому читаемость исходной Texture2D не требуется. CPU-восстановление по UV поддерживает поворот, отражение и tight packing, сохраняет исходный прозрачный холст и пропорции. При неподдерживаемых или повреждённых данных остаётся `MISSING_ICON`, без выдуманной картинки.

Unity API вызывается в главном потоке; максимум одна пиктограмма за кадр. Временные текстуры уничтожаются, предыдущий `RenderTexture.active` восстанавливается в `finally`. Игровые текстуры и файлы не изменяются. Ограничения защиты: исходный холст до 512×512, область атласа до 1024×1024, PNG до 512 КиБ, уникальные PNG одного прохода до 64 МиБ. Превышение фиксируется как отсутствие конкретной пиктограммы, предмет сохраняется.

PNG получает ключ SHA-256 от точных байтов. Два фоновых HTTP-работника отправляют их на `POST /api/icons/<sha256>.png`, затем manifest на `POST /api/registry`. Manifest публикуется только после успешной передачи всех PNG этого прохода: ошибка одной пиктограммы сохраняет предыдущий каталог backend до повтора. Для этих запросов используется отдельный HTTP-клиент с таймаутом 10 секунд, независимо от короткого таймаута синхронизации инвентарей. Оба пути требуют `X-VRM-Token`, используют только loopback HTTP и не перенаправляют запросы. Ошибка отправки реестра не блокирует отдельную очередь контейнеров. При отказе API выполняется повтор через 30 секунд. Диагностика содержит этап, HTTP-статус либо класс ошибки без URL, токена и тела ответа. После успешного прохода реестр периодически отправляется повторно; токен, пути установки, имена игроков и миров в manifest не включаются.

## Полнота и ограничения

`definitionsFound` — число записей именно наблюдавшегося `ObjectDB.m_items`; `registered` — число уникальных определений с доступным SharedData. Дополнительная диагностика содержит число распознанных ItemDrop, невалидных записей, дублей ID, коллизий hash, найденных и экспортированных вариантов пиктограмм. `complete` выставляется только при точном равенстве зарегистрированных записей исходному массиву, отсутствии пропусков и дублей. Даже полное покрытие текущего ObjectDB не подтверждает полноту мира или обнаружение всех контейнеров.

Модификации, которые не добавляют свои определения в ObjectDB или изменяют только неизвестные частные поля без изменения наблюдаемых свойств, требуют отдельного адаптера. Точные string ID сохраняются при коллизии hash; hash-псевдоним нельзя разрешать неоднозначно. Текущий exporter допускает только проверенную API-поверхность Valheim 1.0.20. Большой manifest свыше 3 МиБ сохраняет предыдущий каталог и оставляет предупреждение.

Настоящие игровые PNG остаются локальными данными пользователя. В публичный репозиторий входят только исходный код экспортёра, документация и синтетические тесты; игровой графики, DLL и сохранений здесь нет. Локальное извлечение не означает разрешения на дальнейшее распространение игровых изображений.

## Проверки

```powershell
powershell -ExecutionPolicy Bypass -File plugin/build.ps1
dotnet run --project tools/registry-runtime/tests/RegistryAlgorithms.Tests.csproj -c Release
powershell -ExecutionPolicy Bypass -File tools/registry-runtime/verify-runtime-plugin.ps1
```

Алгоритмические проверки используют синтетический CSV и RGBA-массивы: Unicode, CSV-кавычки, поворот/отражение, обрезанный Sprite, прозрачность, смещение атласа и tight geometry. Транспортные проверки вызывают тот же `RegistryUpload` с синтетическими POST-функциями: отказ пиктограммы запрещает публикацию manifest, повтор восстанавливает передачу, два работника завершаются до manifest, отказ manifest диагностируется отдельно. IL-аудит запрещает прямые вызовы записи игровых данных, изменение реестра и локализации; операции с текстурами ограничены отдельным методом экспорта. Эти результаты не заменяют проверку Unity GPU, выполнения нового плагина в реальной игре и реального изменения количества в сундуке.

## Обновление уже установленного собственного плагина

`scripts/update-plugin.ps1` использует существующий проверенный `data/plugin-install.json`. При работающем Valheim он возвращает `DEFERRED` и не заменяет установленную DLL. При закрытой игре проверяются независимые квитанции установки, хеши DLL/CFG и проверенная игровая сборка. Предыдущие DLL, CFG и квитанции резервируются в приватном `data/integration-backup/`; исходная квитанция отсутствия собственных файлов сохраняется для совместимости с удалением плагина. CFG не переписывается: токен и SourceId сохраняются побайтно.

Перед и после атомарной замены только собственной DLL сравниваются относительные пути, размеры и SHA-256 всех остальных файлов установки, а также список каталогов. После проверки обновляется независимая квитанция. Неизвестные, изменённые или перенаправленные через junction пути отвергаются. Сценарий не запускает и не останавливает игру.

```powershell
powershell -ExecutionPolicy Bypass -File scripts/test_update.ps1
powershell -ExecutionPolicy Bypass -File scripts/update-plugin.ps1
```

Восемь проверок обновления используют только временную имитацию установки, фиктивные старые бинарные данные и неизменяемый маркер сохранения. Игровая библиотека читается только как проверенная ссылка. Эти тесты проверяют совместимость с удалением, сохранение CFG, повторный запуск, отклонение изменённых файлов/квитанций/сборки и отсрочку при имитации работающей игры.
